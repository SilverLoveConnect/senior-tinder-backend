## 0. 역할과 작업 원칙

너는 이 앱을 처음부터 만드는 **시니어 풀스택 개발자이자 영어 교육 콘텐츠 설계자**다.
사용자는 나 한 명뿐이고, 앱스토어 배포는 하지 않는다. **운영 비용 0원**이 목표다.

작업은 반드시 아래 순서로 진행하고, **각 단계가 끝나면 멈추고 내 확인을 받는다.**

1. 리서치 → `research.md`
2. 계획 → `plan.md`
3. 구현 → plan.md 승인 후, 작게 쪼갠 단계별로

### 절대 규칙
- 리서치·계획 결과를 **채팅창 구두 요약으로 끝내지 말 것.** 반드시 md 파일로 작성한다.
- 파일을 만들거나 수정하기 **전에** 항상 먼저 보여줄 것:
  1. 무엇을 바꾸는지
  2. 왜 이 방법을 택했는지 — 이 방법밖에 없었는지
  3. 다른 방법은 무엇이 있었는지 — **대안 코드도 함께**
  4. 각 방법의 장점·단점
  5. 나중에 내가 직접 고치려면 어디를 어떻게 고치면 되는지
- 추측 금지: 라이브러리 버전, API 무료 한도, 브라우저 지원 여부는 **공식 문서를 웹에서 확인**하고 출처 URL과 확인 날짜를 남긴다.
- 가장 비싼 실패를 피할 것:
  - 정해진 계층(화면 → 훅/서비스 → 저장소)을 건너뛰는 함수
  - 같은 일을 하는 함수·API 엔드포인트·테이블 중복 생성 → 새로 만들기 전에 기존 것부터 검색
  - 데이터 스키마를 바꿀 때 버전/마이그레이션 없이 덮어쓰기

## 1. 요구사항

### 1-1. 하루 흐름 (총 20분)

| 시간 | 알림 | 내용 | 목표 소요 |
|---|---|---|---|
| 아침 `[기본값] 07:00` | 푸시: "오늘의 표현 5개" | 새 표현 학습 | 약 12분 |
| **저녁 20:00** | 푸시: "퀴즈 시간" | 복습 퀴즈 15문항 | 약 8분 |

- 두 알림 시간 모두 설정 화면에서 바꿀 수 있게 한다.
- 하루 20분 안에 끝나도록 분량을 맞춘다. 화면별 예상 소요 시간을 plan.md에서 계산한다.

### 1-2. 교수법: 청화식 (Audio-Lingual Method)
흐름: **듣기 → 따라 말하기 → 패턴 연습 → 대화 암기 → 즉시 피드백.** 문법 설명은 최소화한다.

- **소리 먼저**: 새 문장은 텍스트를 가린 채 원어민 음성부터 들려준다. 한 번 탭하면 영어 텍스트, 한 번 더 탭하면 한국어 뜻.
- **따라 말하기 (mimicry)**: 원어민 음성 → 내 발화 → 비교. 긴 문장은 뒤에서부터 덩어리를 늘려가는 **backward build-up**을 지원한다.
  - 예: `a bit late` → `running a bit late` → `Sorry, I'm running a bit late.`
- **대치 연습 (substitution drill)**: 표현의 틀은 그대로 두고 빈칸만 바꿔 말한다.
- **변형 연습 (transformation drill)**: 긍정 → 부정 → 의문, 시제 바꾸기.
- **대화 암기**: 상대방(A) 대사는 원어민 음성으로 나오고, 내 대사(B)는 내가 말한다. 끝나면 역할을 바꿔 한 번 더.
- **즉시 피드백**: 말하자마자 맞은 단어/틀린 단어 표시 + 원어민 음성 다시 듣기 + 내 녹음 듣기.

### 1-3. 레벨: 초급 / 중급 / 고급

| 레벨 | 기준 (CEFR 참고) | 문장 길이 | 대화 길이 | 특징 |
|---|---|---|---|---|
| 초급 | A1–A2 | 4–8단어 | 4턴 | 고빈도 일상 표현, 현재·과거 |
| 중급 | B1 | 7–12단어 | 6턴 | 구동사, 부드럽게 말하는 표현 |
| 고급 | B2–C1 | 10–18단어 | 6–8턴 | 뉘앙스, 비즈니스·면접 상황 |

- **처음 레벨**: 첫 실행 때 레벨 테스트(1-6)로 정한다.
- **자동 승급** `[기본값]`: 최근 10학습일의 퀴즈 정답률이 85% 이상이면 다음 학습일부터 한 단계 위 레벨로 올리고 알림을 보낸다.
- **하향은 자동으로 하지 않는다.** `[기본값]` 최근 10학습일 정답률이 50% 미만이면 레벨 테스트 재응시를 권유만 한다.
- 레벨이 바뀌어도 이전 레벨에서 배운 문장은 복습 퀴즈에 그대로 나온다. 진도는 레벨별로 따로 기록한다.

### 1-4. 아침: 새 표현 5개
표현 1개당 다음을 만든다.
- 핵심 표현 + 자연스러운 한국어 뜻 + 언제 쓰는지 한 줄
- **파생 문장 3개** (대치 1개 이상, 변형 1개 이상). 각 파생 문장에는 그 말을 끌어내는 **상대방 대사(cue)를 짝으로** 붙인다. 앱의 모든 학습 단위가 "상대방 → 나" 대화 쌍이 되게 한다.
- **그 표현이 들어간 대화 1개** (A=상대방, B=나, 레벨별 턴 수)

진도와 날짜:
- 진도는 **실제 공부한 날(학습일) 기준**이다. 하루를 빠져도 콘텐츠를 건너뛰지 않고 다음에 이어서 한다. "Day N" = N번째 학습일.
- 학습일 = 아침 학습을 끝낸 날.
- `[기본값]` 날짜는 Asia/Seoul 기준, 하루 경계는 새벽 4시.

### 1-5. 저녁 8시: 복습 퀴즈
- 15문항:
  - 1학습일 전에 배운 문장 5개
  - 3학습일 전에 배운 문장 5개
  - 7학습일 전에 배운 문장 5개
- 출제: 해당 학습일의 표현마다 1쌍씩 뽑는다 (대화 속 내 대사 또는 파생 문장 쌍). 직전 퀴즈에 나온 문장은 가능하면 피한다.
- **형식: 상대방 대사 음성을 듣고 → 내 대사를 영어로 말하기.** 텍스트는 가린 상태로 시작한다.
- 채점: 음성인식 결과를 정답과 비교(정규화 후 단어 단위 비교) → 통과 / 다시 말하기 `[기본값] 최대 2회` → 정답 공개 + 원어민 음성 + 내 녹음 비교. 결과는 모두 기록한다.

예외 처리:
- 해당 학습일이 아직 없으면(처음 7학습일) 그 섹션은 건너뛰고 "아직 없음"으로 표시
- `[기본값]` 저녁에 퀴즈를 못 했으면 다음 아침 학습을 시작하기 전까지 풀 수 있고, 그 뒤엔 미응시로 기록
- 학습일 계산은 **함수 하나로 분리**한다

### 1-6. 레벨 테스트 (스스로 응시)
- 언제: 첫 실행 때 1회 + 설정에서 언제든 재응시 + 하향 권유가 떴을 때.
- 시간: 약 10분.
- 청화식에 맞게 **듣기·말하기 중심** 3가지 유형:
  1. **듣고 따라 말하기**: 원어민 문장을 한 번 듣고 텍스트 없이 그대로 따라 말한다. 짧고 쉬운 문장에서 길고 복잡한 문장으로.
  2. **듣고 알맞은 대답 고르기**: 상대방 대사를 듣고 가장 자연스러운 내 대답을 3개 중에서 고른다. 선택지도 음성으로 들을 수 있게.
  3. **상황 보고 말하기**: 한국어 상황 설명 + 상대방 대사 음성 → 내 대사를 영어로 말한다. 허용 답안을 여러 개 미리 준비해 비교한다.
- `[기본값]` 2단계 적응형: 1단계 중급 6문항 → 결과에 따라 2단계 초급 블록 또는 고급 블록 9문항 (총 15문항).
- 채점:
  - 따라 말하기: 단어 일치율 + Azure 발음 점수
  - 대답 고르기: 정답 여부
  - 상황 말하기: 허용 답안과의 단어 일치율
- 레벨 판정 기준 점수는 설정값으로 분리한다. 기본 기준값은 plan.md에서 근거와 함께 제안한다.
- 결과 화면: 판정 레벨, 유형별 점수, 틀린 문장 다시 듣기, 이전 테스트와 비교.
- 레벨 테스트 문항은 일일 콘텐츠와 겹치지 않는 별도 문항 풀(`content/level-test/`)로 만든다. 재응시 때 같은 문항이 반복되지 않도록 **최소 2세트**를 만든다.

### 1-7. 음성 기능
- **원어민 음성 (TTS)**: 상대방과 나의 목소리를 서로 다른 성별의 미국 영어 신경망 음성으로. 0.75배 / 1배속 재생은 클라이언트의 `playbackRate`로 처리한다 (같은 문장을 속도별로 두 번 생성하지 말 것).
- **마이크 인식 (STT)**: 내가 말한 문장을 텍스트로.
- **비교 확인**: 원어민 음성 ↔ 내 녹음을 번갈아 듣기(A/B 비교) + 틀린 단어 하이라이트.
- **발음 채점**: 학습 화면에서는 버튼을 눌렀을 때만 호출. 정확도·유창성·완성도·운율 점수 + 단어별 점수.

### 1-8. 콘텐츠 품질 규칙 (가장 중요)
- **원어민이 실제로 쓰는 표현만.** 한국 교과서식 문장은 금지. (예: `I'm fine, thank you. And you?` 같은 문장)
- 표현마다 실제 사용 예를 **웹 검색으로 확인**한다 (해외 커뮤니티, 뉴스, 영상 자막 등). 확인한 출처 URL은 콘텐츠 데이터의 `source_check`에 남긴다.
- 레벨 테스트의 "대답 고르기" 오답 선택지는 원어민도 실제로 쓰는 답이 섞이지 않게 한다 (정답이 2개가 되는 문항 금지).
- 전체 콘텐츠(레벨 테스트 포함)에서 같은 표현 중복 금지 → 중복 검사 스크립트를 만든다.
- 한국어 뜻은 직역이 아니라 그 상황에서 한국 사람이 실제로 하는 말로.
- 주제 비중: **일상 50% / 비즈니스·면접 50%.**

| 정시 실행 | 정확히 07:00 / 20:00에 보낼 수 있는 무료 스케줄러. 후보: Supabase `pg_cron` → Vercel 함수 호출 | **Vercel 무료 cron은 부적합**: 하루 1회만 가능하고, 지정한 시각부터 59분 사이 아무 때나 실행됨 |
| 데이터 | Supabase 무료 (학습 기록, 퀴즈 결과, 레벨 테스트 기록, 푸시 구독 정보) | IndexedDB 캐시는 리서치에서 필요성 판단 |

### 비용·보안 안전장치
- Azure는 반드시 **F0(무료) 리소스**로 만든다. 한도를 넘으면 과금되지 않고 요청이 막히는지 리서치에서 확인한다.
- Azure 키를 클라이언트 코드에 넣지 않는다. 서버리스 함수에서 **단기 토큰**을 발급해 쓴다.
- 푸시 발송 함수와 토큰 함수는 비밀값(환경변수)으로 보호한다. Supabase는 RLS를 켜고 내 계정만 접근하게 한다.
- TTS 파일명은 `문장 텍스트 + 음성 이름`의 해시로 만들어, 이미 있는 파일은 다시 생성하지 않는다.
- 앱 안에 **이번 달 TTS 글자 수 / 발음 채점 사용 시간** 카운터를 표시한다.
- 월 예상 사용량(학습 + 퀴즈 + 레벨 테스트)을 계산해 research.md에 넣는다.

## 3. 0단계: 리서치 → `research.md`

아래 항목을 **깊이, 매우 상세히** 조사하고 모든 세부사항을 research.md에 작성해라. 채팅 요약으로 끝내지 말 것.

1. **청화식 교수법**: drill 종류별 정의와 순서, 이 앱 화면 흐름에 각각 어떻게 대응시킬지
2. **아이폰 Safari / 홈 화면 웹앱(PWA standalone 모드)**:
   - `webkitSpeechRecognition` 동작 여부, `lang='en-US'`, 침묵 시 자동 종료, 중간 결과(interim)
   - 마이크 권한 팝업이 매번 뜨는지, 줄이는 방법
   - 오디오 자동재생 제한 (사용자 터치 필요 여부)
   - IndexedDB 데이터가 삭제되는 조건
3. **웹 푸시 (아이폰)**: 지원 iOS 버전, 홈 화면 설치 조건, manifest 요구사항, 권한 요청은 사용자 터치가 필요한지, VAPID 키, 서비스 워커, 알려진 안정성 문제와 대응
4. **정시 스케줄러 비교표**: Vercel 무료 cron의 한계, Supabase `pg_cron` + `pg_net`, 그 밖의 무료 옵션 — 실행 시각 정확도, 무료 한도, 설정 난이도, 시간대(UTC↔KST) 처리. **Supabase 무료 프로젝트가 일시정지되는 조건**과 매일 쓸 때 문제가 없는지
5. **Azure AI Speech**:
   - F0 무료 한도(TTS 글자 수, STT 시간), 한도 초과 시 동작
   - 브라우저 JS SDK로 발음 평가하는 방법 (reference text, granularity, prosody)
   - 단기 토큰 발급 방식
   - 대화용 음성 2개 추천 (상대방 / 나)
6. **음성인식 결과와 정답 비교**: 대소문자·구두점·축약형(`I'm` / `I am`)·숫자(`ten` / `10`) 정규화, 단어 단위 diff 알고리즘, 통과 기준
7. **레벨 테스트 설계 근거**: 듣고 따라 말하기(elicited imitation) 방식의 배치고사 연구, 다단계 적응형 테스트 구조, CEFR 레벨 설명과 판정 기준 잡는 법
8. **자동 승급 기준**: 정답률 기반 승급 사례와 85% / 10학습일 기본값이 적절한지
9. **학습일 기준 스케줄러 엣지 케이스**: 첫 7학습일, 아침은 했는데 저녁 퀴즈를 빠진 날, 아침 없이 저녁만 연 날, 레벨 변경 직후, 하루 경계(새벽 4시)
10. **하루 20분 분량 검증**: 표현 5개 + 파생 3개 + 대화 1개 + 퀴즈 15문항이 20분 안에 들어오는지 화면별 계산
11. **월 예상 사용량**과 무료 한도 대비 여유 (계산식 포함)
12. 모든 항목에 공식 문서 출처 URL과 확인 날짜

**research.md 작성 후 멈추고 내 확인을 기다려라.**

## 4. 1단계: 계획 → `plan.md`

research.md가 승인되면, 실제로 읽은 문서와 결정 사항을 바탕으로 **상세 plan.md**를 작성해라.

1. 접근 방식 상세 설명 — 왜 이 구조인지, 버린 대안과 버린 이유
2. 폴더 구조와 생성·수정될 **파일 경로 전체**
3. 데이터 모델 — 콘텐츠 JSON 스키마, 레벨 테스트 문항 스키마, Supabase 테이블(학습 기록, 퀴즈 결과, 레벨 테스트 결과, 레벨 변경 이력, 푸시 구독, 사용량)과 마이그레이션 파일
4. **실제 코드 스니펫**:
   - 학습일 계산 + 퀴즈 출제 (1·3·7학습일 전)
   - 텍스트 정규화 + 단어 단위 비교
   - 레벨 테스트 2단계 분기 + 점수 → 레벨 판정
   - 자동 승급 / 하향 권유 규칙
   - TTS 일괄 생성 스크립트 (해시 캐시 포함)
   - Azure 토큰 발급 서버리스 함수
   - 푸시 구독 저장, 발송 함수, 07:00 / 20:00 스케줄 설정
   - 녹음 / 재생 / A·B 비교
5. 화면 목록과 흐름:
   - 첫 실행: 홈 화면 추가 안내 → 알림 허용 → 레벨 테스트
   - 아침: 오늘의 표현 5개 → 대치·변형 연습 → 대화 연습(역할 교대)
   - 저녁: 퀴즈 15문항 → 결과
   - 설정: 알림 시간, 레벨, 레벨 테스트 재응시, 이번 달 사용량
6. 고려사항과 트레이드오프
7. 구현 순서 — 작게 쪼갠 단계, 각 단계마다 "어떻게 확인하는지"
8. 확장 아이디어 — **구현하지 말고 제안만** (예: 틀린 문장 다음 날 재출제, 저녁 퀴즈에 그날 아침 문장 추가)

**plan.md 작성 후 멈추고 승인을 기다려라.**

## 6. 완료 기준

- 아이폰 홈 화면에서 앱을 열어 **첫 실행 → 알림 허용 → 레벨 테스트 → 레벨 자동 설정**까지 동작
- 아침 알림 → 오늘의 표현 5개 → 대화 연습이 끊김 없이 동작
- **저녁 8시 퀴즈 알림**이 정시 근처 `[기본값] ±5분`에 도착하고, 퀴즈 15문항이 학습일 기준으로 출제됨
- 원어민 음성 재생, 내 녹음 재생, A/B 비교, 틀린 단어 하이라이트 동작
- 발음 채점 버튼으로 점수 확인 가능
- 승급 조건을 채우면 다음 학습일부터 레벨이 올라감
- 이번 달 Azure 사용량이 앱에 표시되고 무료 한도 안
- 학습일 계산·퀴즈 출제·정규화·레벨 판정·승급 규칙 단위 테스트 통과
- Azure 키와 푸시 비밀키가 클라이언트 번들에 포함되지 않음
